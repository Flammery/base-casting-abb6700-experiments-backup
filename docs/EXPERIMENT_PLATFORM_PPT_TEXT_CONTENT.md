# ABB 6700 打磨实验平台 PPT 逐页文字稿

> 本文档只整理每一页可以直接使用的文字内容，不包含版式、配色和配图建议。内容以当前 `experiments/base_casting_abb6700` 项目的文档和代码实现为准。

## 第 1 页｜ABB 6700 打磨实验平台流程

### 副标题

从主程序选面、路径候选生成到 RobotStudio 验证

### 页面正文

本项目是一套面向 ABB 6700 打磨实验的离线规划与验证平台。主程序负责选择需要加工的曲面、确定机器人和工具配置，并将项目状态导出为 JSON；实验平台负责读取这些数据，完成加工区域分区、工件安装位姿枚举、UV 轨迹生成、避孔处理、可选的机器人杆系避障粗筛以及最优候选选择；最后再把结果打包成独立的 RobotStudio 工作站进行验证。

这套平台的目标不是直接给出机器人安全认证结论，而是把从加工对象定义到验证工作站生成的过程标准化，并保留每个候选产生、筛选和淘汰的依据，使实验结果能够重复、比较和追溯。

## 第 2 页｜实验平台的完整处理流程

### 页面正文

整个实验流程从主程序开始。首先在主程序中选择需要打磨的曲面，并确定机器人运动学模型、关节初始状态、工具 TCP 和工件坐标系等配置。项目数据导出为 `.rsp.json`，如需覆盖机器人 MDH 参数、关节 seed 或杆件包络，还可以额外导入 `.rsc.json`。实验平台加载这些数据后，将每个选中曲面转换成独立的 planning region。

进入实验平台后，可以根据工艺需要对区域进行手动分区，也可以指定哪些 region 或 patch 需要进行机器人杆系避障。如果两项都不需要，则直接设置工件相对机器人基座的安装位置、转台角度和允许加工的空间窗口。点击 Runner 后，平台会枚举安装位姿和加工方向，依次完成窗口判断、UV 光栅生成、三维投影、避孔处理、姿态生成和可选的杆系避障粗筛，然后为每个 region 选择最优结果。

最终结果被转换为 RAPID 程序，并按 region 或 patch 生成独立的 RobotStudio 工作站。实验平台负责生成候选和内部粗筛，RobotStudio 则负责检查完整机器人单元中的连续运动、碰撞、构型、轴限位和实际环境安全性。

## 第 3 页｜主程序选面、机器人配置与 JSON 交接

### 页面正文

主程序是实验数据的入口。用户首先在三维模型上选择需要打磨的曲面，选中结果以 `selected_path_face_regions` 的形式保存。每个 region 都保留自己的加工面、三角网格关联和边界信息，平台不会把多个加工面预先合并成一条跨区域路径。这样可以保证后续的分区、轨迹生成、最优选择和 RobotStudio 导出都以 region 为独立单位进行。

主程序同时保存工件模型、picked origin、工件坐标系、抛光工具、TCP、机器人配置和关节状态。执行“导出到脚本测试”后，这些数据被写入完整的项目快照 `.rsp.json`。该文件是实验平台的主要输入，已经包含项目内部的 `robot_config` 和 `joint_state`，因此在不进行特殊杆系实验时，只导入 `.rsp.json` 即可运行。

`.rsc.json` 是可选的机器人杆系覆盖文件，可以独立提供六轴 MDH 参数、关节限位、初始 seed 以及各杆件的包络尺寸。显式导入后，实验平台使用这套配置做 IK、FK 和杆件粗筛；未导入时使用项目内机器人配置，并把所有碰撞杆段统一近似为半径 100 mm。该覆盖不会修改原始 `.rsp.json` 的项目结构。

## 第 4 页｜加工区域分区与避障设置

### 页面正文

实验平台加载 planning regions 后，首先判断加工区域是否需要进一步拆分。对于几何范围较大、工艺方向不同或需要分别选择最优安装位置的区域，可以使用手动 UV 分区功能。分区操作在二维参数域中完成，通过 boundary、slab 或 pick 等方式定义 patch 边界，不会直接切割原始 STL。分区结果继续保存在新的 `.rsp.json` 中，而 patch 的二维边界、来源 region 和编号关系记录在 manifest 文件中。

分区之后，再决定哪些 region 或 patch 需要进行机器人杆系避障。避障设置允许选择目标区域，并定义局部 U、V 方向的扩大比例以及法向 N+、N− 的高度范围。这些参数用于从工件网格中提取本轮需要参与碰撞检查的局部墙体。避障设置只有在对话框中点击“应用”后才会对下一次 Runner 生效，磁盘上存在 avoidance JSON 并不代表当前运行已经启用避障。

分区和杆系避障是两条相互独立的支线。分区解决“一个加工区域是否需要拆成多个独立规划单元”的问题，杆系避障解决“机器人采用哪一种绕 TCP 法向的姿态更容易避开局部墙体”的问题。如果两项都不需要，流程可以直接进入工件位姿和加工窗口设置。

## 第 5 页｜工件安装位置、转台旋转与坐标转换

### 页面正文

实验平台通过 Model X、Y、Z 和 Turntable RZ 设置工件相对机器人基座的安装位姿。X、Y、Z 控制工件在机器人 base/world 坐标系中的平移，RZ 控制工件绕转台竖直轴的旋转。每一组 X、Y、Z、RZ 都代表一个需要评估的安装候选，Runner 会在用户给定的范围内批量枚举这些组合。

规划过程中必须区分 model、world/base 和 wobj 三套坐标。`position_model` 用于 UV 参数化、STL 射线命中、三角面编号和表面法向计算；`position_world` 或 `position_base` 用于加工窗口判断、base Y 对齐、IK、FK 和 confdata 计算；`position_wobj` 用于写入 RAPID robtarget。三者遵循“model → world/base → wobj”的变换关系，不能混用。

工件位置变化时，场景中的模型和 RAPID 使用的 wobj 必须同步更新。当前实现根据实验位姿和 picked origin 计算新的 wobj，其中 picked origin 只参与一次旋转，禁止重复叠加。姿态先在 world 坐标系中生成，再转换为相对 wobj 的四元数。工具 TCP 只表示工具几何和工艺参考点，不能用来补偿路径方向或工件安装误差。

## 第 6 页｜点击 Runner 后的批量枚举与加工窗口判断

### 页面正文

点击 Runner 后，程序首先读取项目、planning regions、分区 manifest、工件位姿范围和本次运行参数，然后建立多层枚举循环。外层依次遍历安装位置 X、Y、Z，转台角度 RZ，每个 planning region 或 patch，以及 long-side、short-side 两种主要进给方向。每个组合都是一个独立候选，不同 region 之间不会在这一阶段连接成一条连续加工路径。

每个候选进入轨迹规划之前，必须先通过加工窗口判断。程序把当前 region 或 patch 的有效几何转换到 world/base 坐标系，检查其整体是否落在允许的 X、Y、Z 加工范围内。当前策略采用保守的整区域门控：只有整个区域都在窗口内才继续生成路径；如果区域有一部分超出窗口，则跳过当前 pose、angle 和 region 组合，而不是裁掉超出部分后继续加工。

默认实验参数包括 50 mm 的扫描间距、50 mm 的路径采样步长和 6 mm 的边缘余量，默认加工窗口的 X 范围为 1500–2500 mm，Y 范围为 −1050–1050 mm。所有跳过、覆盖和成功情况都会记录到结果目录及 `summary.json` 中，便于解释某个候选为什么没有产生轨迹。

## 第 7 页｜UV 光栅、三维投影与加工姿态生成

### 页面正文

通过加工窗口后，程序开始为当前 region 或 patch 生成几何轨迹。首先读取该区域关联的 STL triangles，并建立局部 raster chart，包括原点、U 轴、V 轴和参考法向。程序根据 patch 边界或选中曲面的边界确定长边和短边方向，再按照选定的进给方向在二维 `clip_polygon` 内生成等间距 scanlines。

每条扫描线与二维加工域求交后得到一个或多个有效 interval。如果存在 `exclude_polygons`，这些孔洞或禁入区对应的区间会从扫描线中扣除。随后，程序沿 raster chart 的法向向 STL 发射射线，把每个二维 UV 采样点重新投影到三维曲面。每次命中都会得到 XYZ、`face_id` 和三角面的 facet normal，从而形成 model、world 和 wobj 三套坐标下的 waypoint。

加工姿态由表面法向和机器人基座方向共同确定。当前规则令 TCP 的局部 +Z 指向表面法向的反方向，即 `TCP +Z = −surface normal`；TCP 的局部 +Y 则尽量投影对齐机器人 base +Y，以减少姿态无规则旋转。相邻四元数还会通过点积检查在 `q` 和 `−q` 之间选择连续表示，避免数值上出现不必要的姿态翻转。

二维 polygon 决定实际加工边界，STL 负责提供三维落点和表面法向。如果 raycast 在扫描过程中失去曲面命中，当前 run 必须立即结束，不能简单删除缺失点后把孔洞两侧继续连接成一条贴面直线。

## 第 8 页｜Auto 避孔判定与 Cell 抬刀

### 页面正文

`auto` 模式不是一套独立的轨迹几何算法，而是普通 raster 和 hole-aware raster 之间的自动分流器。程序首先检查当前 `clip_polygon` 与 `exclude_polygons` 是否存在正面积重叠。如果孔洞位于加工域内部或穿过加工域边界，都会触发 hole-aware；只有点接触或边接触而没有实际面积重叠时，不会仅凭这一条件触发避孔。

如果没有发现有效的 exclude 重叠，程序先生成普通 raster，再检查同一条 scanline 是否出现多个彼此分离的有效 run。出现 split-scanline 说明扫描线中间存在真实孔洞、凹口、ray miss 或选面缺口，因此同样切换到 hole-aware。只有 exclude-overlap 和 split-scanline 两项都不成立时，才保留普通 raster，并记录 `planner_reason = regular-raster`。

进入 hole-aware 后，程序先从 scanline 中扣除 exclude intervals，并在 ray miss 处立即断开 run。随后根据相邻扫描线上的 run 是否存在重叠关系，把它们组织成多个独立 cell。每个 cell 内部仍然保留完整的往复加工轨迹，避免因为避孔而破坏正常的扫描顺序；只有从一个 cell 转移到另一个 cell 时才执行抬刀。

Cell 转场采用局部法向抬刀策略。程序在当前 cell 的末端点沿该点的局部表面法向退出 150 mm，通过 MoveL 完成局部退刀；再使用 MoveJ 从当前离面端点移动到下一 cell 的离面接近点；最后沿下一 cell 起点的局部法向 MoveL 接近表面并继续加工。这里的 150 mm 是当前 `SAFE_DISTANCE`，它不是统一的世界 Z 安全平面，而是分别依据两个端点的局部表面法向计算。

当前实现不运行 A*，也不会生成跨孔的贴面 connector。避孔的核心原则是保持 cell 内轨迹完整，并通过“局部退刀—离面 MoveJ—局部接近”避免 TCP 在孔洞或无表面支撑区域上方继续贴面直穿。

## 第 9 页｜局部墙体障碍如何判定

### 页面正文

机器人杆系避障使用的障碍并不是整个工件模型，而是当前加工区域附近、位于指定 UVN 范围内的非支撑表面。这样可以把碰撞计算集中在与当前加工任务最相关的局部几何上，减少不必要的三角形数量，同时避免把机器人正在接触的加工面错误地判定为障碍。

程序首先确定完整支撑面。对于未分区 region，原始加工 `face_ids` 直接作为支撑面；对于分区 patch，程序从路径实际命中的 `face_id` 开始进行支撑面生长，并强制合并源加工面，保证路径附近所有合理支撑区域都被识别。完整支撑面会从后续障碍集合中排除，因此“加工面 cells 与墙体 cells 不相交”是算法的数据不变量，而不只是预览时的颜色规则。

确定支撑面后，程序把支撑面全部顶点投影到局部 U、V 平面，计算二维凸包，并根据用户设置的 U、V 百分比围绕中心扩大。然后沿局部法向 N+ 和 N− 拉伸，形成一个封闭的 UVN 棱柱。工件网格中位于该棱柱内部或穿过棱柱边界的 cells 被选入局部范围，再减去支撑面 cells，剩余部分就是本轮杆系碰撞粗筛使用的墙体障碍。

采用凸包会有意覆盖孔洞、凹入区域和狭窄连接，从而获得稳定、单一的外边界。正式 collision mesh 还会根据数量限制进行降采样，墙体三角形通常控制在约 6000 个以内。因此，这个局部墙体是实验平台内部粗筛使用的简化障碍模型，并不等同于 RobotStudio 中包含转台、夹具、底座和周边设备的完整环境。

## 第 10 页｜姿态限制与机器人杆系避障粗筛

### 页面正文

当前杆系避障不会重新规划 TCP 的 XYZ，也不会改变避孔 cell 的拓扑和加工点顺序。它只允许整条路径的 TCP 围绕局部法向进行滚转，依次尝试从 `−90°` 到 `+90°`、间隔 `15°` 的 13 种固定姿态。无论选择哪一种 roll，TCP 的位置保持不变，TCP +Z 始终等于负表面法向，因此改变的是机器人杆系在空间中的展开方式，而不是加工轨迹本身。

对于每个 roll 候选，程序从完整路径中最多均匀抽取 7 个代表点进行内部粗筛。首先对每个抽样点求解 IK，并把上一个成功关节解作为下一个点的 seed；如果任一点无解，则该姿态不能标记为 validated。随后检查相邻抽样点之间的最大实际关节跳变是否不超过 40°，并要求所有抽样点的最小 `|J5|` 不低于 6°，以减少明显的构型跳变和腕部奇异风险。

IK 通过后，程序使用 FK 计算各机器人杆件的中心线位置，并结合杆系配置中的包络半径与局部墙体三角网格进行碰撞和间隙检查。最小间隙按照“杆件中心线到三角形的距离减去杆件包络半径”计算，要求抽样最小间隙不低于 5 mm。导入 `.rsc.json` 时使用文件中的 MDH、关节限位、seed 和杆件包络；未导入时只能使用默认的细中心杆近似，漏检风险更高。

只有所有条件都通过的姿态才会得到 `baseline-validated` 或 `alternative-validated` 状态。程序在这些姿态中选择“抽样最小机械臂净间隙”最大的结果，TCP roll 大小不参与排序；间隙完全相同时保留固定姿态库顺序。内部 validated 只表示最多 7 个离散姿态通过了简化模型粗筛，不能代替连续运动和完整机器人外壳的碰撞验证。

## 第 11 页｜候选保存、诊断结果与 Optimal 选择

### 页面正文

Runner 会保留所有非空几何路径及其诊断信息，而不是只保存最终最优结果。候选目录按照安装位置、转台角度、region 和进给方向分层组织，同时生成 `all_candidates.csv`、`coverage_by_pose.csv`、`robot_avoidance_trials.csv` 和 `deferred_paths.csv` 等记录。这些文件用于说明每条路径是在窗口判断、几何生成、IK、碰撞、间隙还是其它阶段被接受或淘汰。

普通区域和仅进行避孔处理的区域使用位置评分选择最优候选。当前规则首先最小化整条路径的 `max(abs(world_y))`，使加工路径尽量靠近机器人 base Y 中心；如果多个候选在该指标上并列，再最小化 `max(abs(world_x))`。每个 region 或 patch 独立选择一个最优结果，不会因为另一区域的评分而改变当前区域的选择。

启用杆系避障的区域采用更严格的准入规则。只有状态为 `baseline-validated` 或 `alternative-validated` 的候选才能进入 `optimal_paths`；随后直接最大化抽样最小机械臂 clearance，不再使用 TCP roll 或普通区域的 world-Y/world-X 评分。已经生成几何路径但 IK unresolved、发生碰撞、间隙不足或未完成验证的结果仍可保留在 `candidates` 中供 RobotStudio 诊断，但不能作为避障区域的最优结果。

最终结果写入 `optimal_paths/<region_label>/`，并通过 `optimal_selection.csv`、`optimal_records.json` 和 `summary.json` 建立索引。其中 `summary.json` 保存本次运行使用的输入、策略、参数、候选数量和限制，是解释一次实验结果的首要依据。需要特别注意，候选目录中存在 RAPID 文件只表示路径已经生成，并不表示该路径已经通过杆系避障或完整安全验证。

## 第 12 页｜RAPID 生成与 RobotStudio 工作站打包

### 页面正文

每个 region 或 patch 的最优记录会被转换为独立的 RAPID 路径。正常加工点以及沿局部法向的接近和退刀使用 MoveL；hole-aware 路径中两个 cell 的离面端点之间使用 MoveJ。Waypoint 的 world 姿态先转换为相对 wobj 的四元数，位置则写入 `position_wobj`。程序保留原项目中的 tool 和 wobj 名称，并根据 world Y 等信息生成必要的 confdata，同时使用 `ConfL \Off` 适应实验路径验证。

RobotStudio 打包程序读取 `optimal_records.json` 和最优 RAPID 文件，从中分离 tooldata 与 wobjdata，生成 `CalibData.mod` 和 `VALIDATE_<region>.mod`。然后从只读模板复制一份 `.rsstn` 工作站，只修改场景工件组件的 X、Y、Z 和 RZ，最后生成同名的 `.robotstudio_job.json`。RobotStudio 插件读取 job 文件，等待虚拟控制器就绪，再把校准模块和验证模块加载到对应任务中。

每个最优 region 或 patch 都生成一套独立工作站，避免不同区域的路径、位姿和模块相互覆盖。模板工作站本身不会被修改，但多个复制出的工作站仍然复用模板虚拟控制器状态，因此验证时应一次只打开一个。场景组件名称和 RAPID wobj 名称属于不同概念：前者控制三维场景中工件实体的位置，后者控制机器人程序中的坐标变换，两者必须分别正确设置。

完成导出后，用户在实验平台中点击“导入 RobotStudio 验证”，即可为当前最优结果生成或打开对应验证工作站。该步骤的目的不是证明路径已经安全，而是把实验平台中选出的几何和姿态候选交给完整 ABB 单元继续检查。

## 第 13 页｜RobotStudio 最终验证与平台能力边界

### 页面正文

实验平台已经完成加工面和 patch 的独立规划、加工窗口筛选、UV raster、STL ray-lift、孔洞和缺口处的 cell 抬刀、可选的机器人杆系姿态抽样粗筛、候选追溯、最优结果选择以及独立 RobotStudio 工作站准备。这些能力能够显著减少需要人工检查的组合数量，并为每个结果提供明确的参数和筛选依据。

RobotStudio 或真实机器人单元仍然必须验证完整的 MoveL 和 MoveJ 连续运动、真实 ABB 机器人外壳、工具实体、自碰撞、底座、地轨、转台、夹具和周边环境。同时还要检查路径可达性、机器人构型连续性、轴限位、奇异点、孔边和工件间隙，以及速度、zone、载荷和实际加工工艺安全性。

实验平台的快速预览主要显示 processing geometry，不执行完整的避障 IK/FK，也不能完整表达 RAPID 连续运动。内部碰撞检查最多抽样 7 个点，杆件和墙体都可能使用降采样或简化包络，并且没有计算完整的连续 swept volume。因此，“已经生成工作站”不等于“已经验证通过”，“内部 validated”也不等于机器人安全认证。

正式实验验收时，应同时保存输入 JSON、分区和避障 sidecar、`summary.json`、候选与最优 CSV、RAPID 模块、RobotStudio 工作站以及关键验证截图。只有把实验平台的可解释候选与 RobotStudio 的完整单元验证结合起来，才能形成完整、可复现的验证闭环。

## 文字内容使用说明

上述 13 页文字按照“先讲整体流程，再逐步展开输入、预处理、位姿、轨迹、避孔、避障、选择和验证”的顺序编写。制作 PPT 时可以把每页的第一段作为页面介绍，其余段落作为原理与实现过程；如页面空间有限，可保留每段首句和最后的结论句，将中间参数说明放入演讲备注。
