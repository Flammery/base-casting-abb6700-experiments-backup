# 机械臂替代姿态避障原理

> 本文用于理解当前实验代码，不代表算法已经完成，也不构成机器人安全验证结论。
> 当前实现仍会继续修改。正式生产前必须使用完整机器人、工具、环境模型和连续运动验证。

对应代码：`experimental_algorithms/robot_pose_avoidance.py`。

## 1. 当前问题和算法边界

区域路径规划首先决定 TCP 接触点、加工顺序、孔洞避让以及 cell 之间的抬刀/转场动作。机械臂避障随后在不改变接触点的前提下，尝试改变机械臂腕部姿态，寻找较少干涉的逆解。

当前算法只改变 TCP 绕自身局部 Z 轴的滚转角，不改变：

- TCP 的 XYZ 位置；
- TCP 局部 Z 轴，即工具轴/表面接触方向；
- 已经生成的加工点顺序；
- 孔洞避让和抬刀路径的拓扑。

因此它是“小姿态库筛查”，不是能够自动绕开障碍物重新规划 XYZ 轨迹的通用避障规划器。

## 2. 为什么绕 TCP 局部 Z 轴旋转

设原路径点姿态四元数为 `q_waypoint`，局部 Z 轴滚转四元数为：

```text
q_roll = [cos(theta/2), 0, 0, sin(theta/2)]
```

候选姿态使用右乘：

```text
q_candidate = normalize(q_waypoint * q_roll)
```

右乘表示旋转发生在 TCP 自身坐标系中。因为 `q_roll` 只绕局部 Z 轴旋转，局部 Z 轴方向保持不变，而局部 X/Y 轴绕 Z 轴转动。这样可以在尽量不改变加工法向的情况下改变腕部和各连杆的空间位置。

代码还会检查相邻四元数点积。如果点积为负，就将新四元数整体取反。`q` 与 `-q` 表示同一个空间姿态，这一步只用于维持数值表示连续，避免导出路径出现不必要的四元数符号跳变。

## 3. 小型替代姿态库

当前固定姿态库为：

```text
-90°, -75°, -60°, -45°, -30°, -15°, 0°, +15°, +30°, +45°, +60°, +75°, +90°
```

对应名称为：

| 滚转角 | 名称 |
| ---: | --- |
| 0° | `base_y` |
| +15° | `tcp_z_p15` |
| -15° | `tcp_z_m15` |
| +30° | `tcp_z_p30` |
| -30° | `tcp_z_m30` |
| +45° | `tcp_z_p45` |
| -45° | `tcp_z_m45` |
| +60° | `tcp_z_p60` |
| -60° | `tcp_z_m60` |
| +75° | `tcp_z_p75` |
| -75° | `tcp_z_m75` |
| +90° | `tcp_z_p90` |
| -90° | `tcp_z_m90` |

整条 region/patch 路径使用同一个滚转角，而不是每个路径点独立选角度。这样可以减少腕部频繁扭转和构型跳变，也便于把结果导入 RobotStudio 检查。

## 4. 单个候选姿态如何筛查

在生成姿态候选前，算法先从最终路径提取 `Waypoint.face_id`，作为加工 patch 所在
支撑面的种子。种子沿共享边邻接三角形生长，只有同时满足以下条件才加入支撑面：

- 与当前相邻三角形的法向夹角不超过 `12°`；
- 与路径种子参考法向的夹角不超过 `12°`；
- 三角形中心到种子参考平面的距离不超过 `3 mm`。

生长结果代表 patch 所在的完整支撑面。它从墙体距离网格中排除。完整支撑面的三角形
先投影到统一 UV 平面，U/V 分别围绕投影轮廓中心按比例扩大，再沿 N+/N- 拉伸成封闭
异形体；曲面在本阶段也采用先投影再拉伸。只有位于该异形体内部或与其边界相交、且
不属于支撑面的三角形继续作为墙体障碍。UV 包围矩形不能代替真实支撑面轮廓。
算法不按朝上、朝下或三角形法向正反过滤。

当前墙体网格仍受最多 `6000` 个三角形的实验预算限制，但采样只发生在用户设置的
UVN 范围内，不再用全工件样本补足。

对每个候选姿态，当前流程为：

```text
从路径中抽取代表点
  -> 第一个代表点允许自由寻找 IK 构型
  -> 后续代表点锁定到种子构型附近求 IK
  -> FK 得到机器人连杆线段
  -> 检查连杆与去除支撑面后的墙体障碍网格碰撞及最小间隙
  -> 检查构型数量、最大关节跳变和 J5 奇异区
```

候选只有同时满足以下条件才被接受：

1. 路径中存在可评估点；
2. 所有抽样点 IK 成功；
3. 抽样点没有检测到连杆碰撞；
4. 抽样最小间隙不小于要求的安全阈值；
5. 抽样结果不跨越多个机器人构型；
6. 最大关节跳变不超过阈值；
7. J5 不进入设定的近奇异范围。

当前默认参数为：

- 最多抽样 7 个代表点；
- 导入 `.rsc.json` 时使用其中的 MDH、关节限位、初始状态和各段配置包络；
- 未导入时所有实验杆段使用统一半径 100 mm；
- 最小间隙阈值 5 mm；
- 最大关节跳变 40°；
- 最小 `|J5|` 为 6°。

这些是实验参数，不是 ABB 机械臂的安全参数。

## 5. 最小间隙的定义

对抽样姿态中的每一根机械臂线段和碰撞网格三角形，先计算线段中心线到三角形的最短距离，再减去当前碰撞半径：

```text
clearance = distance(segment_centerline, triangle) - link_envelope_radius
```

所有抽样点、所有参与检查的连杆和所有网格三角形中的最小值，记为该候选姿态的 `minimum_clearance_mm`。

候选首先必须满足：

```text
minimum_clearance_mm >= required_clearance_mm
```

然后才参与姿态角比较。当前默认要求为 5 mm，可以通过 runner 的 `--avoidance-min-clearance` 参数调整。

这里的“最小间隙”仍只是实验估计值，因为当前碰撞网格会降采样，而且只检查代表路径点，没有覆盖两个路径点之间的连续运动。

### 5.1 导入杆系配置后的碰撞半径

实验 UI 第一行可导入主程序“保存杆系配置”生成的 `.rsc.json`。实验会验证：

- schema 为 `robot_studio_mechanism_config`；
- `kinematic_model` 为 `mdh`；
- 当前 ABB 实验为六轴；
- 六段均存在正的 `envelope_width` 和 `envelope_height`。

主程序杆系显示/碰撞线段使用下式将矩形包络近似为胶囊半径：

```text
segment_radius = max(10 mm, 0.45 * min(envelope_width, envelope_height))
```

`ABB 6700 Style.rsc.json` 当前得到的 J1 到 J6 半径依次为：

```text
198.0, 148.5, 144.0, 117.0, 103.5, 90.0 mm
```

这些配置半径比统一 100 mm 回退更贴合各杆件差异，但仍是简化包络，不等于机器人每处真实外轮廓。

## 6. 当前选择规则

### 6.1 单个安装位置内选择姿态

先剔除没有达到间隙阈值或其他硬条件失败的姿态，再选择：

```text
抽样最小机械臂净间隙最大
```

TCP 局部 Z 滚转角大小不参与排序。多个有效姿态的抽样最小间隙完全相同时，保持姿态库的固定顺序，使结果可复现。

如果 13 个姿态都没有通过，状态为 `fallback-unverified`。原始路径仅用于诊断，不进入正式 candidate/optimal 导出。

### 6.2 不同安装位置之间选择避障区域最优解

只有已经位于用户设置加工范围内的区域才会生成候选。避障区域的安装位置选择规则为：

```text
加工范围合格
  -> 抽样最小间隙达到阈值
  -> 抽样最小机械臂净间隙最大
  -> 完全相同时保留稳定扫描顺序
```

避障区域不使用 TCP roll、`abs(model_y)` 或 `max(abs(world_y))` 评分。

普通区域以及带孔但没有被用户指定为避障区域的路径，仍沿用原来的 Optimal-Y 规则，不受本算法影响。

## 7. 带孔区域与机械臂避障顺序

当前正确流程是：

```text
生成普通/孔感知加工路径
  -> 完成孔洞避让、cell 分组、抬刀和转场
  -> 对最终路径应用替代姿态库
  -> 做机械臂 IK/FK、碰撞和间隙筛查
```

机械臂筛查必须面对最终会执行的路径。如果先筛查机械臂，再由孔感知规划器增加抬刀或转场动作，新动作可能引入未检查的碰撞。

未来如果机械臂避障开始改变 TCP 的 XYZ 路线，还必须在改线后再次检查孔洞、边界和工艺约束。

## 8. 日志字段

`robot_avoidance_trials.csv` 对每个安装位置、转台角、region/patch、feed variant 和姿态候选记录：

- `pose_name`、`roll_degrees`；
- `accepted`、`selection_status`、`selected_pose`；
- `sampled_waypoints`、`ik_failures`；
- `collision_count`、`collision_links`；
- `minimum_clearance_mm`、`required_clearance_mm`；
- `configuration_count`；
- `max_joint_jump_degrees`、`min_abs_j5_degrees`；
- `message`。

`summary.json.support_surface_growth` 另外记录每个避障区域的种子数、支撑面 cell 数、
剩余障碍 cell 数、参考法向/平面误差、优先障碍数和实际障碍三角形数。

candidate 记录还会保存最终选择姿态的 `avoidance_min_clearance_mm` 和 `avoidance_required_clearance_mm`，便于解释最优结果。

## 9. 已知问题

当前实现至少有以下限制：

1. **最多只抽样 7 点。** 例如一条 56 点路径抽取 `0、9、18、28、37、46、55` 时，第 25 点发生的碰撞会被漏掉。
2. **没有检查连续扫掠体。** 两个离散点都不碰撞，不表示中间的 MoveJ/MoveL 一定不碰撞。
3. **连杆仍是简化包络。** 导入 `.rsc.json` 后仍只是配置线段胶囊；未导入时统一
   100 mm 半径。两者都不是随关节变化的 ABB CAD 外壳。
4. **局部网格仍可能被降采样。** UVN 范围内的墙体超过预算时仍会压缩到约 6000 个三角形。
5. **未包含完整工具、环境和自碰撞。** 当前主要检查机械臂连杆与工件。
6. **IK 构型搜索有限。** 第一个点选择到的构型可能不是整条路径的最好构型。
7. **固定姿态库很小。** 它不能证明库外不存在更好的姿态，也不能完成真正的空间绕障。
8. **最小间隙不是认证数据。** 它继承抽样、细杆和稀疏网格误差，只适合当前实验排序。
9. **当前支撑面恢复面向近似平面。** 强曲率加工面可能只恢复局部范围；日志和颜色预览
   必须确认绿色区域没有越过圆角进入墙面，也没有过早停止。

因此日志中的 `validated` 实际含义是“通过当前抽样实验筛查”，不能理解为完整可达或安全认证。

## 10. 后续改进方向

建议按以下顺序升级：

1. 对所有加工点以及抬刀/转场点做 IK 和碰撞检查；
2. 对 MoveJ/MoveL 插值，检查连续运动；
3. 使用真实连杆包络、工具模型、夹具和周边环境；
4. 使用更完整的碰撞网格或可靠的空间索引，避免简单步长降采样；
5. 为首点搜索多个合法机器人构型，并比较整条路径的连续性；
6. 将间隙、关节限位余量和奇异性余量写入统一诊断；
7. 完成上述验证后，再确定正式安全阈值和候选姿态角度范围；
8. 最后使用 RobotStudio/真实控制器验证生成结果。
## 2026-07-22 当前连续性策略（覆盖本文旧的硬配置锁说明）

- 每个代表点都调用 `SerialKinematicsSolver(...,
  lock_configuration_to_seed=False)`；公共 `solvers.py` 暂不修改。
- 第一个点使用项目/导入杆系的初始关节状态，后续点使用上一个成功关节解
  作为 seed，使数值求解优先沿上一姿态继续。
- `[cf1,cf4,cf6,cfx]` 仍记录为诊断，但配置分区变化不再直接拒绝 IK。
  特别是 J6 在 0°附近的小幅连续跨越不能被当成翻腕或不可达。
- 连续性由相邻成功解的实际最大关节角差判断，当前实验阈值仍为 40°；同时
  保留 J5余量、IK成功率、FK连杆碰撞和最小间隙条件。
- 单次姿态状态区分为 `validated-clear`、`validated-interference`、
  `clearance-insufficient`、`joint-discontinuous`、`near-singularity`、
  `ik-unresolved` 等。配置变化本身不是失败状态。
- 13 个姿态均未通过时保留原始 base-y非空路径及诊断，但它不能进入避障
  `optimal_paths`。只有 `baseline-validated`/`alternative-validated` 可进入
  最优选择。
- `robot_avoidance_trials.csv` 使用精简字段记录安装 XYZ、转台角度、区域、
  工具 roll、是否选中、状态、抽样干涉、最小间隙、最大关节跳变和原因。
- 该算法仍只检查最多 7 个代表点和简化机器人包络，不构成 ABB/RobotStudio
  或真实单元的安全认证。
